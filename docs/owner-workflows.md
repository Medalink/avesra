## Claude project draft

The native catalog owner resolves one current immutable owner-selected application
and one eligible window/process. A dedicated native worker performs UI Automation
reads only inside that exact window. A bounded snapshot has at most128 controls,
depth12, five seconds of new-work admission and256 UTF-8 bytes per semantic label.
Password controls, hidden elements, disabled controls and foreign-process elements
are excluded. Truncation is explicit and cannot become a complete binding.
Opaque native choices expose role, name, automation ID and supported patterns;
the webview cannot supply executable selectors or COM objects. Provider calls may
outlive the deadline; the actual worker retains ownership until they return.

Protected owner setup must bind observed semantic controls for the project
selector, project heading, new-chat action, document route and prompt.
Current app revision and each control's unique bounded semantic identity are
rechecked on every operation. Freshness means the actual New Chat operation,
observed `/new` composer state, exact project heading and an empty input before
writing. A permanent server conversation UUID is not required before submission;
an empty edit field or RuntimeId change alone is insufficient.
The project heading must directly label the prompt through the provider's actual
UIA `LabeledBy` relationship. Native `CompareElements` verifies that relationship
against the exact selected heading during binding and before/after writing.
A matching sidebar label plus a generic `/new` URL does not prove association.
Absent this provider relationship, the initial adapter remains unsupported.
Existing unsent text prevents project/new-chat mutation. Owner selection is
configuration only, separate from an ordinary exact project-target action grant.

The whole accepted request resolves application, project, new-chat requirement and
exact prompt text independently of model proposals. Before each native mutation,
recheck original accepted source, session, action epoch, cancellation, remaining
budget, exact app/process/window, foreground, expected project and control identity.
Select the configured project, observe its exact project route and heading, create
a fresh chat, observe its new-composer route and empty input, fill the exact text,
then read the same field and verify project/new-chat identity again. No submission
operation is part of this draft workflow. A partial or uncertain effect is retained
as unknown; retry cannot silently replace a draft or create another chat.

The initial source pins the observed Claude2.9939.2.0 package, accepts only a
read-only Document ValuePattern reporting an actual `https://claude.ai/project/UUID`
route and later `/new` state, a text heading for the project, the observed English
`New Chat` InvokePattern and a writable prompt ValuePattern. These route meanings
and New Chat label occur in the installed application resources, inspected read-only
without user data. Their exposure through UIA is unproven and may be absent. In
that case binding refuses rather than guessing a DOM selector or asserting ready.
The Settings Bind & allow button explicitly both saves this target and grants only
FillPrompt. The native worker consumes its original at-most30-second probe, derives
all semantic identities from native choice IDs and reobserves before committing.
Schema14 rejects older readers that do not understand this permission variant.
The supported whole accepted grammar is `Open APP for the PROJECT project and type
TEXT into a new chat`, optionally prefixed by Avesra and ending with one period.
It also accepts the exact owner workflow form `Open APP for the PROJECT project,
create a new chat, and type exactly TEXT`. This is a closed grammar alternative;
it does not infer prompt text or permit submission.
In the `type exactly TEXT` form the entire text suffix, including a final period,
is literal payload. Only the alternative's final `into a new chat.` permits
discarding the sentence period outside the requested text.
The full request is bounded to4096 UTF-8 bytes. Text is preserved exactly;
the operation emits neither Enter nor submission. A native final receipt stores
the exact requested-text digest and binding revision, not another prompt copy.
After each one-shot mutation, bounded read-only scans poll the required semantic
postcondition under the original action deadline and a nonrenewable 15-second
adapter cap. The next mutation happens only after its actual prerequisite is
observed. No Invoke or SetValue call is retried after a result or error. Missing
elements during rendering may be polled; changed authority, foreground, ambiguous
identity, nonempty prior draft or provider failure aborts instead of retrying.

Prefer UIA ValuePattern when writable. Microsoft documents that multiline inputs
can expose only read-only TextPattern. A Unicode SendInput path, if implemented,
must first obtain an explicit visible automation session with exclusive user-input
handoff; an accepted task or a frontend boolean alone cannot create that token.
It must run only on the current input desktop, bind original HWND/process/integrity
and exact focused element immediately before each bounded Unicode chunk, and never
emit Enter, clipboard commands or shortcuts. User intervention withdraws it.
Windows focus can still change between the last check and input delivery; document
this residual race and treat partial delivery as unknown without automatic retry.
No background or non-input-desktop typing is allowed. Missing supported patterns,
fresh-chat evidence or handoff remains NeedsInput/Unsupported.

## Browser consumers

Gmail enumeration must bind the configured authenticated account and actual Inbox
scope, individual message IDs and dates, newest-first ordering, thread expansion
and pagination/completeness evidence. Ten conversation rows are not ten messages.
Reuse C4's original actual job, exact document/lifecycle, host permission checks,
single content publication and cleanup settlement. Content stays transient; typed
message references, dates and bounded conclusions may be retained as task results.
Every delivered/shipped/out-for-delivery conclusion must name its message source;
missing bodies or ambiguous packages must remain incomplete.

X readiness requires exact configured profile/account and intended origin after
navigation, plus actual logged-in ready state. Login/CAPTCHA remains user input.
This request permits no draft, send or publish. A ready generic page or matching
title alone is insufficient. Browser account metadata never comes from a guessed
URL or extension installation identity.

No UI, focus, input, account access or workflow operation is invoked during source
implementation. Root-owned direct spoken evidence must record OW1/OW2/OW3 separately;
compilation and manual agent operations do not establish those passes.
