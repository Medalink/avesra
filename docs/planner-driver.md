# Paired actor registration and accepted planner/reply transport

This slice follows the durable native conversation and exact-app producer. It cannot activate voice: there is still no qualified runtime profile or current-profile producer. The normal reasoning/TTS entry point must remain separate from generated-voice setup preview. A model, browser page, extension, frontend flag or received transcript cannot create a native accepted turn.

## Explicit native actor registration

The paired companion is the trusted native authority for its OS-backed owner setup, subject to the existing same-user local-code threat boundary. Spark does not independently verify Windows Hello. The native registration command must consume the original one-use protected Settings proof before its first await, read the durable owner/current OS principal, and bind the exact paired device, acknowledged control session/generation and immutable owner actor. The Settings action must describe that it registers this local owner with the paired Spark. Do not send the Windows SID, enrollment vectors or raw authentication evidence over this route.

A separate strict versioned HTTPS registration request carries a native-generated request UUID, actor UUID, current control session/action epoch and original expected registration revision. It is authenticated with the current paired-device credential and admitted only while the control session is unlocked, unpaused and action-enabled. Mute/deafen are separate from action permission. The server binds one immutable owner actor registration to that device in its transactional authentication metadata. A repeated exact read can reconcile an uncertain write, but a different actor or unknown/malformed existing row must not replace it. Explicit revocation is revision-bound and invalidates outstanding planner/reply authority. Neither registration nor an owner label creates an application/browser grant. Device revocation always invalidates its actor binding at admission and during in-flight work.

Native owner configuration is an assertion from the authenticated companion, not proof derived from a model response or an arbitrary remote actor ID. Only the protected native adapter may issue registration; no extension/page forwarding or general webview HTTP proxy exists. Final publication rechecks the original native proof/context after blocking reads and at commit initiation. Lost replies are reconciled by exact request/device/actor/revision; there is no automatic replacement registration or silent rollback.

## Accepted request ownership

An opaque stored native planner claim is the source of a reasoning request. The existing actual ledger worker must transition one accepted turn into one unique planner request transactionally, retain bounded accepted text and original actor/device/session/action provenance, and reject cancelled, suspended, already-linked or answered records. Exact app commands may finish through the prior native resolver; they need no model. The request deadline is fixed at native admission and must include queue/transit/driver time, with no renewed lifetime after retries. Restart suspends uncertain planning; it never reissues it automatically.

The public controller route checks paired-device authentication, exact active actor-registration revision, current acknowledged session/action epoch and a source-turn/request replay record. The native request is a privileged assertion of durable acceptance by that companion; `accepted: true` is neither required nor sufficient. The server-generated private model request ID is distinct from all client IDs. Bound request body, pending count, per-device retained replay entries, global actual driver jobs, sends and idle waits. Reject resource exhaustion rather than evicting an ID while a response could still exist. A missing/expired control heartbeat, Stop/pause/lock/disconnect, actor/device revocation or action-epoch change cancels publication and the owned request. Capture-only mute must not revoke an already accepted request.

Cancellation retains actual ownership until the HTTP/model operation finishes or the configured backend confirms cancellation. A dropped network future alone must not free a second model slot or claim that GPU work stopped. If the Local Studio backend lacks request cancellation proof, record cancellation pending/unavailable and retain the bounded actual job until its completion/deadline semantics are known; do not reset unrelated serving engines.

## Local Studio reasoning adapter

Use the existing Local Studio deployment owner and authenticated proxy. A private Avesra configuration selects an exact recipe/deployment, model ID/artifact revision, endpoint and credential file; no request/model output chooses a URL, credential, model path or serving engine. Keep the endpoint loopback or explicitly certificate-bound to the configured Spark. Disable redirects and environment proxy inheritance. The adapter may read deployment metadata and send an explicitly admitted accepted request; it must never start, swap, evict or modify Local Studio automatically to satisfy it.

Before readiness, validate the installed API's actual status/model identity and supported text/structured-result capability. Downloaded artifacts, an HTTP 200, a configuration label or historical synthetic probe is not current readiness. Implement a bounded typed adapter against the inspected API shape; leave unconfigured/incompatible states explicit. No floating dependency changes, model loads, inference probes or evaluation runners are part of this source-only phase.

The planner sees the accepted user text and only separately authorized context. It returns a bounded untrusted typed answer, NeedsInput question, or proposed operations. No planner field is an authority ID, grant, approval, executable command or observed postcondition. Unknown/extra fields, malformed result, nonterminal/truncated completion and mismatched deployment/request IDs are rejected. For the initial answer path, no tools are executed and no browser/app facts are fabricated; action proposals remain NeedsInput until a native exact resolver or concrete owner clarification freezes their scope. General planner prose cannot establish that an effect succeeded.

## Durable reply and normal TTS

The native worker accepts a correlated result only for the actual current stored planner claim and action context, validates its exact source and fixed deadline, then stores an immutable reply revision under that accepted turn. No response received after cancellation may create a replacement turn/reply. A question with no tools remains a legitimate conversation; it is not converted into an empty AcceptedIntent. Task outcome speech must instead reference native observed finalization, preserving UnknownEffect explicitly.

Only an opaque stored reply handle may enter normal TTS. The public synthesis stream binds registered actor, accepted turn/reply/request revision, current paired session, independent playback epoch and exact selected generated-voice identity including audio and metadata digests. The native companion must recheck reply state and current output authority before opening the device lease. No arbitrary setup-preview text endpoint is added. Deafen/Stop/pause/lock/disconnect/output device or voice changes withdraw output; mic mute alone preserves it.

Keep private streaming TTS ownership and fixed synthesis deadline, native startup/prebuffer headroom, paced packet age, sequence/utterance replay checks, final complete/truncated distinction and submitted-versus-heard drain semantics. The preview transport primitives may be reused internally only after this separate accepted-reply admission. Nothing in this contract asserts a live actor registration, planner readiness, reply, generated voice or audible output.

## Actor registration wire and persistence contract

The first transport slice is strict actor protocol 1 on `/actors`: request UUID, control session UUID, positive action epoch, and one tagged command. Register carries the native owner's actor UUID and immutable local-owner revision; it is create-only for the authenticated paired device. Status is read-only. Revoke carries the exact actor and registration revision. Responses echo request/session/action context and return either no binding or the actual device/actor/local-owner revision/server registration revision/original registration request/revoked state. All UUIDs are non-nil. Unknown fields and omitted required fields fail; the route cannot register a grant or accept a transcript.

Authentication metadata advances transactionally from schema 1 to schema 2, adding one owner binding per device, with unique registration revision and original request ID. Older databases must have no pre-existing new actor table; schema 2 must match its exact supported SQL/indexes and reject attached triggers. Preserve existing device/pairing data. An occupied unversioned store is rejected using literal internal-name prefix filtering across all object types. Register does not overwrite or revive an existing binding. Revoke is exact-revision idempotent and keeps the immutable tombstone. A new paired-device identity may explicitly register the same durable local actor; actor UUID itself is not globally unique across devices.

The server must verify device activity and current action-session ownership again immediately before commit initiation, under its bounded actual writer ownership. Status/revoke may inspect an existing revoked owner binding, but a revoked paired device cannot use the route. In-flight planner admission must also consult binding revocation; registration state alone is not reasoning readiness. This first storage checkpoint is dormant until the protected native command and current action-session route are integrated.
