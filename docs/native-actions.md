# Native action adapters

## Repeated checks and the first effect boundary

The actual execution owner supplies one opaque `EffectAuthority`. Its `current`
method repeatedly checks the original dispatch, grant/consumed approval, native
cancellation and fixed monotonic deadline. Its separate `commit` method rechecks
that same authority and marks the first possible OS mutation exactly once.
Composite prompt workflows commit before launch/focus, then recheck current
authority before each later Invoke/SetValue; they never request a second commit
or renew the original action lifetime. Any later error remains an unknown effect.

Read-only Diagnostic catalog adapters use repeated current checks and cannot
commit an OS mutation. They may finalize success only after actual read admission,
a validated matching typed report, and a final current check inside the result
transaction adjacent to commit. That transaction revalidates the original permit
and policy; the callback checks only original cancellation/clock, without native
I/O or a reentrant Store borrow. Their receipt has
no crossed-write marker. Returning a report without admission cannot succeed.
The separate browser ReadExecution protocol retains its existing authority path.

## C3 first-action source integration

This slice adds explicit protected action permissions and one exact-command coordinator. The native coordinator consumes an actual opaque DurableTurn before claiming planning. The same ledger worker reads the original accepted text and resolves only `open <learned name>`, `launch <learned name>`, or `set speakers volume to <integer 0..100> percent`, with the existing optional single Avesra address. Unsupported, ambiguous or ungranted commands retain the same opaque turn for the C2 planner. Its version-2 typed launch/absolute-volume proposals now resolve against the same native catalog and explicit grants during the original planner completion transaction. Missing targets or grants remain needs-input, and proposal text cannot claim successful execution. The original capture epoch remains provenance; only current action/session/owner/registration authority controls accepted work. Spoken acceptance remains unqualified.

Visible unlocked Settings exposes separate explicit Launch permission for an exact saved app alias and Set volume permission for one native-enumerated stable output endpoint named speakers. Each grant/revoke consumes current Windows management verification and is rechecked on the actual worker immediately before its transaction. Alias discovery/remembering alone grants nothing. Schema 11 adds bounded immutable action-permission metadata paired transactionally with the existing ledger grant. Revoke commits atomically and signals active precommit cancellation synchronously; it never claims rollback of an observed or unknown effect. At most 128 permission records are retained; exhaustion requires explicit future management rather than silent eviction. Only one active speakers permission per actor is allowed. No model or WebView supplies executable paths, native grant objects, accepted transcripts, approval flags or observed outcomes.

Task linking freezes a typed application or volume target with original source, exact grant/action revision and accepted payload in one transaction. Applications bind immutable app and alias revisions; volume binds the exact stable endpoint and native target UUID. Legacy app-only links remain readable under their original invariants. Pending exact-source cancellation is checked during task preparation and execution. Existing native effect adapters retain actual worker ownership through observed finalization and uncertain results. No automatic retry, restart replay or unmute is introduced.

Settings shows at most 50 recent actor-filtered durable task records with exact-source cancellation, separate verified/unsupported/needs-input/unknown states and no exposed dispatch authority. Runtime working state tracks actual admitted native work; microphone mute does not delete accepted tasks. UI cancellation is lookup by stored task identity in the native panel cache, then exact source/revision revalidation; neither UI labels nor saved rows reconstruct a DurableTurn. Worker-issued monotonic snapshot sequences order status replies and pre-dispatch/final projections, so late reads cannot replace current task/cancellation metadata. Status and permission waits do not block the independent bounded cancellation lane. A failed mutation preserves the latest displayed snapshot and asks for reconciliation. Caller disposal shares the effect's withdrawal atomic from before enqueue, while actual worker ownership survives disposal. Root-owned static builds and source review apply; no tests, live app effects or device volume changes are run by this slice.

Entry points: action panel open/close/read (bounded current native owner and panel); grant/revoke (consumed Windows proof and same-worker commit); accepted-turn coordinator (opaque DurableTurn only, no IPC constructor); exact resolver/link/dispatch (same Store owner and frozen DispatchSession); task status/cancel (actor filter and stored exact source); C2 fallback (same unresolved handle, one planner claim); typed planner proposal finalization (same worker, original deadline and native grants); app discovery, microphone capture, voice qualification and playback (unchanged).

Native effects execute only after the controller durably claims an exact action revision and the companion independently validates its accepted intent, actor grant, current session/epochs, target revision and required local approval. Model proposals and webview arguments cannot supply that authority. Adapters accept resolved native targets; they never infer a target from a display label, arbitrary shell command, URL scheme or executable argument string.

Volume targets bind a stable WASAPI output endpoint ID. The adapter reads current scalar volume and mute separately, validates percentages within 0–100, changes only the requested scalar, then reads back the same endpoint. It does not automatically unmute. A relative request must first resolve to an exact bounded absolute value that becomes part of the accepted action payload. Store the actual previous value for an explicit later restoration; never claim rollback merely because the setter returned successfully. Endpoint disappearance, failed readback or an observed external change produces an uncertain/failed observed outcome and does not trigger blind retries.

App targets are explicit owner-selected catalog records with immutable revision, canonical executable/package identity and bounded allowlisted arguments. Discovery is read-only. Launching must use the selected identity, preserve existing user work, and verify the resulting process/window rather than assume API success proves the intended app opened. Focus, project/account selection and visible text remain separate fresh preconditions for later input. Administrative prompts remain under the owner's control.

The Windows lock/session hook, pause/stop and disconnect must invalidate admission before a new OS effect. Once an effect has crossed its commit boundary, report its observed outcome or uncertainty; cancellation is not rollback. Background COM work must own its apartment lifetime, avoid UI/runtime mutexes during OS calls, and return bounded categorized results without secret-bearing window content.

Current boundary: the Windows volume adapter is implemented and statically compiled, including stable endpoint resolution, separate mute observation, pre-commit authorization callback and verified/uncertain readback. It is connected to the opaque accepted-turn coordinator in source, but has not been invoked or qualified on a device. The executable app adapter uses the same owned worker, with an immutable persistent catalog, fresh executable identity validation and typed process/window observations. Native Settings can select an observed window hint before registering the new identity; runtime focus is limited to one eligible matching instance with empty saved arguments. Missing hints, ambiguity or unproven argument context yield NeedsInput before effects. Packaged activation now uses exact current-user AUMID/full-version registration, native hints, bounded existing focus and a distinct package-process observation. These paths are uninvoked/unqualified; the qualified live accepted-turn producer remains absent. Server action admission remains closed. The owner is gaming, so no audio controls, app launches, focus, UIA or browser operations may be exercised during implementation. Microsoft defines [endpoint scalar volume](https://learn.microsoft.com/en-us/windows/win32/api/endpointvolume/nf-endpointvolume-iaudioendpointvolume-setmastervolumelevelscalar) as an audio-tapered normalized control value, not a linear acoustic amplitude measurement.

The companion now owns one synchronous effect worker and its separate native-actions ledger. A process-wide admission lease and Windows exclusive owner-file handle are acquired before ledger open/recovery and retained by the actual worker until it exits. Dropping a reply receiver or timing out a caller cannot detach COM work or free its slot. Management changes enter the same bounded queue and immediately cancel the active pre-commit lease; consumed approvals can be revoked without making them reusable. Current action-epoch/session changes, pause/stop/lock/disconnect, owner permission loss and explicit management revocation invalidate that lease synchronously. Mic mute/unmute and deafen/undeafen affect media only; speech-service/device failure does not revoke already accepted native work.

The coordinator claims a durable exact revision, rechecks its grant, accepted payload, consumed approval, cancellation and fixed monotonic lifetime immediately before commit, and records observed success or uncertainty without replay. Schema 4 stores bounded typed volume/mute before/after and application identity/process/window observations with an immutable original outcome in the same transaction, bound to dispatch, target, actor and action revision; the native receipt preserves the same observation. Later reconciliation cannot promote an originally unknown observation into native-observed success. A crash before this result transaction leaves an unknown effect and no invented restoration value. Read-before/read-after cannot identify every transient external change overwritten between reads.

This is source integration with dormant action admission: a fresh installation has no configured volume targets or application aliases, the authenticated accepted-intent producer is still absent, and owner/voice readiness remains closed. Protected native Settings now supports explicit discovered app selection and alias persistence; mapping selection grants no execution right. No action route or webview effect setter was enabled, and no native volume operation was invoked. Protected volume target setup and the opaque accepted-turn coordinator are implemented in this slice. Qualified live owner acceptance, real action proof and restoration UI remain outstanding. Earlier adapter Clippy passed; the new integration requires its own integrated build. No automated tests or live effects were run.

Accepted capture provenance and live action authority are distinct. `DispatchSession.capture_epoch` is frozen native/controller-derived provenance retained with the accepted task and exact dispatch binding; it is not replaced with the latest microphone epoch. The worker observes only the current action epoch and session/owner/paused authority. It retains the same job and cancellation slot across capture-only changes, revalidates durable grant/approval before OS commit, and finishes the original dispatch after commit even if cancelled. The new opaque accepted-turn coordinator supplies frozen provenance from its durable acceptance input; arbitrary old capture epochs are never an independent source of authority. The qualified live producer remains unavailable.
