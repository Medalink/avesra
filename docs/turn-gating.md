# Native accepted conversation boundary

A final transcript and speaker embedding are observations, never an accepted intent or tool authority. The native gate binds each observation to the paired device/session, capture and action epochs, exact microphone endpoint, configured ASR/speaker revisions and utterance ID. Incomplete, stale, repeated, missing or malformed observations abstain. Unknown overlap/echo evidence abstains; absence of a detector is not clean audio. Profile matching uses a normalized representation and a calibrated threshold/margin belonging to that exact qualified profile revision and endpoint. No threshold is supplied by an utterance, model confidence, imported pass flag or UI setting.

At initial capture admission and final analysis, construct current context from the actual acknowledged native session while holding Runtime.local, then the acknowledged-session mutex. The same local lock serializes connection-generation changes and acknowledgment publication. Check exact expected session, capture epoch, connection generation and present capture/readiness/mode conditions inside that critical section; a successful earlier asynchronous check is insufficient. Retain local ownership through final gate analysis so replacement/disconnect cannot interleave between context derivation and admission. These entry points remain closed without qualified profile evidence.

Qualification and enrollment selection remain distinct. The gate's qualified-profile token has no deserialization or public constructor: the current application cannot manufacture it from a saved candidate or selected reference. A future authenticated native calibration/review path must create and revoke the bound token from actual evidence; this source change does not implement an evaluation runner, collect fixtures or declare qualification. Missing runtime evidence keeps the actual producer in abstention and cannot set enrolled or voice-ready.

No mandatory wake word is imposed. A qualified directed-intent adapter must distinguish a complete assistant-directed request from a context-dependent follow-up, binding its decision to the exact utterance/context and configured adapter revision. A leading assistant name is an optional cue, never sufficient evidence; name-leading commentary to teammates still abstains. Unknown/rejected decisions abstain with or without a name prefix. Whitespace-only final text is malformed. A complete directed request may omit the name. A follow-up additionally requires an opaque single-use invitation derived from a previously accepted conversation turn, an exact context/grant/profile/qualification revision match, a fixed five-second expiry and one of the exact expected responses. A short contextual reply cannot be relabelled a complete request merely to bypass invitation checks. These categories and their positive/negative owner/gaming-conversation evidence must be qualified before enablement.

## Qualification and continuous capture prerequisites

The native qualification owner must bind an exact protected candidate ID/revision, authenticated registered actor and grant revision, stable microphone endpoint, ASR/speaker/signal/overlap/echo/directed-intent adapter and model revisions, and the measured operating points. Its review record identifies the explicit locally observed qualification session, condition breakdown, observation counts, accepted/rejected/abstained outcomes and reviewer authorization. It contains no raw media, imported pass flag, model confidence treated as probability, or default guessed threshold. A02-A05 and the positive/no-wake-word and negative teammate/playback/overlap cases in Plan 001 govern promotion; the saved six segments alone do not supply those results. Native current checks must revoke the token synchronously on candidate, endpoint, actor/grant, adapter/model or session replacement. A persisted report is evidence to revalidate, not a deserializable authority token.

Continuous endpointing requires measured signal/VAD decisions on contiguous fresh samples, an original hard utterance deadline, bounded pre-roll, explicit start/end/cancel ownership and no reuse of utterance IDs. A maximum-duration cutoff is an abstention, not a guessed speech endpoint. Every utterance repeats current qualified identity/directness checks; silence and rejected/unknown speech remain transient. No continuous producer is enabled until those adapters and the native qualification owner exist. The current fixed 500-frame transport remains explicitly incomplete. Keep the shared speech/effects/background-music output and its actual post-mix stereo playback reference; the existence of that reference does not establish echo cancellation or clean-input evidence.

The qualified profile binds an explicit actor UUID, and the consumed conversation retains that actor, device/session/epochs/grant and profile/qualification revisions as opaque native provenance. Signal sufficiency is separate from elapsed capture time and embedding similarity. A qualified signal adapter must supply measured voiced/total/clipped sample counts; the bound operating point controls minimum voiced duration and maximum clipping. Missing signal evidence abstains, including for short follow-ups. No duration or threshold is inferred from a ten-second transport window.

An accepted conversation token has private fields and is consumed once with a fresh context/profile/grant recheck and a short fixed lifetime. It contains the accepted text, not a tool proposal. It may support a spoken answer with no tool effect. The eventual planner must separately prepare exact typed action payloads, applicable grants and local approvals through the durable controller; it cannot deserialize or promote tool text into an accepted token. No unknown/unaccepted transcript enters UI, durable history, learning or planning.

This token is pre-commit admission. Durable acceptance is the forthcoming planner/store transaction, which must atomically consume current provenance and write the accepted conversation/task before presenting it as accepted. The five-second freshness and capture-epoch checks apply before that boundary. After durable task acceptance, mic mute does not silently delete the task: it stays visible/cancellable and follows the durable controller's independent action authorization/cancellation policy.

Current wiring sends the native producer's validated final analysis through this gate with no qualified profile or actor/grant, and unknown signal/overlap/echo/directedness evidence. It therefore abstains and discards transient text/embedding. There is no qualified-profile constructor, measured operating point, planner transaction or automatic enrollment/readiness activation in this checkpoint. These boundaries are explicit missing implementation/evidence, not passed M3 gates.
