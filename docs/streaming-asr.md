# Incremental ASR

The cache-aware lane consumes contiguous 16 kHz mono PCM under one controller-owned utterance/session/epoch and a fixed 30-second maximum lifetime. Each chunk contains at most 200 ms; transport gaps, context changes, expiry or cancellation destroy the stream and its model caches. Interim text remains transient and cannot become accepted intent, history, identity or permission evidence. Only final text is eligible for the separate owner/overlap/directness gates.

Feature extraction uses the pinned model's own float32 frontend with a bounded rolling PCM window. Frames are emitted once, on the original 160-sample grid, only after their 256-sample right context exists; finalization permits the model's constant right padding. Retained left context covers FFT support and preemphasis. No whole utterance PCM array or file is accumulated. Configuration outside the inspected 16 kHz / 128-feature / FFT512 / hop160 / unnormalized frontend fails closed instead of silently approximating it.

Encoder channel/time/length caches and decoder hypotheses belong to one stream. Feature queues are bounded by the configured chunk and pre-encoder context; accepted model configurations cannot exceed 256 frames per chunk or context. First/subsequent chunk and shift sizes come from the model's streaming configuration. First-step extra pre-encoded dropping is disabled; final-step outputs are retained. The adapter pins causal dw_striding factor8 and its [1,8] sampling/[0,9] cache geometry. At EOF, a 1–7-frame suffix plus nine cached frames produces one additional output through the model's own three left2/right1 causal convolution pads after dropping two cached outputs. The real suffix is passed with final output retention; no application feature zero-padding or silent suffix discard is added. This source-derived boundary handling remains unqualified with actual speech. All generated text and decoder state remain bounded by the utterance duration and output limits.

Implementation and qualification are separate: the rolling frontend/cache adapter and private supervisor stream owner are implemented in source; the existing deployed supervisor still provides batch whole-utterance inference and advertises streaming false. No live or synthetic speech was used to qualify incremental behavior. Private stream ownership/transport integration and actual latency/recognition evidence remain required.

API grounding: [NeMo 3 cache-aware inference](https://raw.githubusercontent.com/NVIDIA-NeMo/Speech/v3.0.0/examples/asr/asr_cache_aware_streaming/speech_to_text_cache_aware_streaming_infer.py), [streaming encoder buffer contract](https://raw.githubusercontent.com/NVIDIA-NeMo/Speech/v3.0.0/nemo/collections/asr/parts/utils/streaming_utils.py), [feature extraction](https://raw.githubusercontent.com/NVIDIA-NeMo/Speech/v3.0.0/nemo/collections/asr/parts/preprocessing/features.py). The official buffer simulates streaming over accumulated features; Avesra must not use its whole-input retention as a live transport buffer.

Private stream requests use operation stream with the existing v1 identity/epoch/fresh-sequence envelope, plus positive contiguous chunk_sequence and Boolean final. request_id is the immutable utterance worker UUID across all chunks; expires_at_ms is identical to the first packet. Chunks hold at most200ms PCM, and the complete stream at most30s. Only one stream owns the lane between packets, with a2s idle/processing watchdog and fixed first-packet deadline. Cancellation works between chunks as well as during inference; it destroys the child/caches. Completed/rejected stream UUIDs have a bounded31s tombstone window. Replies bind request/session/epoch/chunk sequence and exact model revision; interim text remains unaccepted.

asr-streaming.config.json explicitly selects supported attention context [70,1], rather than the model's first/default [70,13]. Other supported right contexts0/6/13 require explicit configuration. The new option is off in existing batch configs and no image/service was replaced. A configured streaming capability is distinct from loaded_unqualified state and never grants voice readiness. Python3.12 syntax compilation on Spark passed without imports, model loading or inference.

The Rust private client now negotiates the configured ASR streaming capability and holds one owned lane permit across the whole stream, including asynchronous cancellation after caller drop. It enforces caller-provided contiguous chunk sequence, capture age, fixed wall/monotonic deadline, utterance replay tombstones and exact response session/epoch/model/worker correlation. Cancellation failure retains admission until the full remote lifetime has elapsed; it does not imply remote compute stopped. The controller WSS route below now invokes this client; the native producer is connected behind closed readiness, while VAD/utterance segmentation, qualified readiness and accepted-turn gating remain incomplete. Unknown-speaker transcripts are not published to UI or durable history.

The companion now owns one normal-media producer under the paired control connection's lifetime. It runs only with enrolled+voice-ready native state and a matching acknowledged session/epoch/generation. These prerequisites remain false until qualified setup exists. A fresh certificate-verified WSS acknowledgement opens a new capture window; device/queue opening occurs afterwards and the first frame cannot predate that acknowledgement. One bounded10-second window sends exactly500 native20ms frames, reads processing replies independently of sending, validates every correlation/sequence, and discards the final explicit abstention. This fixed-window transport is not VAD or useful assistant turn-taking; it provides no accepted request/action or speech output. No native/device/service invocation was used to qualify it.

Native frame age now projects the first sample's CPAL capture clock onto monotonic time using that callback's CPAL callback timestamp and entry Instant, rather than stamping completed packets with receipt time. Missing/future/stale device-clock relationships close capture; maximum500ms source age and contiguous native sequence are rechecked before sending. This source-derived clock mapping still needs actual WASAPI delay/drift evidence, including callback dispatch delay and resampler alignment. Window cancellation synchronously closes the native capture gate/queue; local epoch changes also reach the server's permission watch and cancel exact upstream work. Capture-window changes no longer reopen independent playback streams. Readiness remains closed; no repeated ambient inference is enabled by this source checkpoint.

Authenticated WSS /voice-stream now binds a single requested utterance to the current paired control session, device, capture epoch and permissive mode watch. Its first bounded text handshake precedes a fresh server capture-window acknowledgement; native capture must begin after that acknowledgement, with actual callback age checked before send. The server requires first audio within500ms and bounds subsequent arrival against the same monotonic sample-offset timeline (500ms late/100ms future tolerance). This proves bounded transport timing for a conforming native producer, not that an arbitrary paired peer could not supply pre-recorded audio; replay/overlap/owner evidence remains a separate closed gate.

Each binary packet remains at most640 PCM bytes/20ms and MediaSession rejects identity, sequence and sample-offset gaps before any ASR chunk. This initial route caps one utterance at10s and the whole socket operation at25s, including final speaker/auth processing, to keep raw input inside its30s lifetime. It shares bounded speech admission with enrollment, rechecks paired revocation and modes, and invalidates the exact private stream when the socket/control context is lost. Interim replies contain status/correlation only; final transcript and embedding are native-only unaccepted observations. No route output creates a task, history record, actor grant or voice-ready state. Existing deployed controller/service binaries are unchanged.
