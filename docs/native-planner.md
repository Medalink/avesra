# Native opaque-claim transport

This slice connects the existing PlannerClaim to the paired /planner route and the same NativeEffects ledger owner. Its Rust-only entry point consumes that opaque handle; no Tauri command, frontend text field, browser message, imported history or status response may construct a claim. The qualified voice producer remains absent and existing voice analysis still abstains. Implementing this path must not set enrolled or voice_ready.

One actual native coordinator owns preparation, HTTP, correlated cancellation and ledger finalization. Its slot survives disappearance of the calling future and cannot be replaced while blocking DPAPI/owner/store work or cancellation is still running. Dropping the caller withdraws the original claim through its existing cancellation handle. The claim's original monotonic 30-second budget includes all preparation and queues; transport() computes remaining immediately before the one request, never at a renewed admission. Every asynchronous completion checks original cancellation/deadline before publishing or beginning more work.

Admission derives the actual acknowledged control session under Runtime.local and captures its connection generation, paired device and certificate fingerprint. It requires connected/unlocked/unpaused current action permission and the original claim session/action source. Current capture epoch is deliberately not compared with the accepted frozen capture epoch. Mic mute/deafen do not cancel an accepted planner request. No synchronous window getter runs under native locks, and Settings visibility is irrelevant to an already accepted task.

Blocking preparation loads the native current OS owner, saved DPAPI pairing and exact create-only registration intent. The owner/owner revision, device, validated certificate-derived fingerprint and original registered_by must match the claim's immutable registration binding. Recheck current native context after those reads. Fetch actual actor status through the existing pinned-certificate client before planner send and again before finalization; require the exact unrevoked binding. Status is read-only and must not create/repair/register an actor or replace an intent.

Use one non-retried HTTPS planner POST with no environment proxies or redirects, only the configured validated certificate, and the shared 32 KiB request/reply limits. Strictly decode and compare the complete planner context/terminal/response. Any timeout, error, withdrawal or lost caller after send attempts one separately bounded correlated /planner/cancel; cancellation is withdrawal only and cannot establish remote rollback or GPU termination. Keep the actual coordinator through that three-second cleanup allowance, without extending the claim or permitting result publication afterward.

Local explicit actor revocation withdraws an exact matching active planner immediately before its remote revoke attempt. Runtime action changes/disconnect/lock/Stop already signal the claim through NativeEffects. Remote status is a point-in-time observation: cross-host revocation can race a subsequent native commit. The final callback rechecks original cancellation, current native session/action/generation and owner identity at commit initiation; no claim of a distributed atomic transaction or rollback is made. A missing or changed current binding is unavailable, never silently adopted.

Finalization consumes the original claim through the existing actual ledger worker, with a native callback checking exact immutable binding/context and current OS owner outside Runtime.local. A successful transaction returns an opaque StoredReply. No response or transcript is emitted to the webview or synthesized here; normal TTS must separately consume that handle under output/voice authority. If cancellation wins after a durable commit, history may exist but no usable reply handle may be published. Explicit history reconciliation cannot reconstruct such authority.
