# Native opaque-claim transport

This slice connects the existing PlannerClaim to the paired /planner route and the same NativeEffects ledger owner. Its Rust-only entry point consumes that opaque handle; no Tauri command, frontend text field, browser message, imported history or status response may construct a claim. The qualified voice producer remains absent and existing voice analysis still abstains. Implementing this path must not set enrolled or voice_ready.

One actual native coordinator owns preparation, HTTP, correlated cancellation and ledger finalization. Its slot survives disappearance of the calling future and cannot be replaced while blocking DPAPI/owner/store work or cancellation is still running. Dropping the caller withdraws the original claim through its existing cancellation handle. The claim's original monotonic 30-second budget includes all preparation and queues; transport() computes remaining immediately before the one request, never at a renewed admission. Every asynchronous completion checks original cancellation/deadline before publishing or beginning more work.

Admission derives the actual acknowledged control session under Runtime.local and captures its connection generation, paired device and certificate fingerprint. It requires connected/unlocked/unpaused current action permission and the original claim session/action source. Current capture epoch is deliberately not compared with the accepted frozen capture epoch. Mic mute/deafen do not cancel an accepted planner request. No synchronous window getter runs under native locks, and Settings visibility is irrelevant to an already accepted task.

Blocking preparation loads the native current OS owner, saved DPAPI pairing and exact create-only registration intent. The owner/owner revision, device, validated certificate-derived fingerprint and original registered_by must match the claim's immutable registration binding. Recheck current native context after those reads. Fetch actual actor status through the existing pinned-certificate client before planner send and again before finalization; require the exact unrevoked binding. Status is read-only and must not create/repair/register an actor or replace an intent.

Use one non-retried HTTPS planner POST with no environment proxies or redirects, only the configured validated certificate, and the shared 32 KiB request/reply limits. Strictly decode and compare the complete planner context/terminal/response. Any timeout, error, withdrawal or lost caller after send attempts one separately bounded correlated /planner/cancel; cancellation is withdrawal only and cannot establish remote rollback or GPU termination. Keep the actual coordinator through that three-second cleanup allowance, without extending the claim or permitting result publication afterward.

Local explicit actor revocation withdraws an exact matching active planner immediately before its remote revoke attempt. Runtime action changes/disconnect/lock/Stop already signal the claim through NativeEffects. Remote status is a point-in-time observation: cross-host revocation can race a subsequent native commit. The final callback rechecks original cancellation, current native session/action/generation and owner identity at commit initiation; no claim of a distributed atomic transaction or rollback is made. A missing or changed current binding is unavailable, never silently adopted.

Finalization consumes the original claim through the existing actual ledger worker, with a native callback checking exact immutable binding/context and current OS owner outside Runtime.local. A successful transaction returns an opaque StoredReply. No response or transcript is emitted to the webview or synthesized here; normal TTS separately consumes the subsequently published opaque handle under output/voice authority. If cancellation wins after a durable commit, history may exist but no usable reply handle may be published. Explicit history reconciliation cannot reconstruct such authority.


Failure cleanup uses a separate opaque withdrawal-only PlannerRetirement copied from the actual claim, carrying its exact immutable plan. It cannot be deserialized, retry a request or reconstruct a reply. The same ledger owner suspends only an exact pending claim with no reply; already replied/answered/waiting_input history is preserved. This bookkeeping remains permitted after claim expiry because it removes active state, not grants authority. Claim post-commit expiry/cancellation, undelivered successful claim receipts and failed finalization use the same primitive on the actual worker. Native transport failure queues exact retirement and waits for its actual result; queue/storage failure remains an explicit unconfirmed cleanup requiring history/restart reconciliation, never a claim that the pending row was cleared.


## Source checkpoint

The Rust-only planner::answer entry point now consumes PlannerClaim, owns one retained coordinator and uses the actual paired certificate/device/session/action context. Native preparation and the final ledger callback both revalidate OS owner, saved pairing and original registration intent under the existing owner-read slot, outside Runtime.local. Exact actor status is read before the non-retried request and after its terminal reply. The fixed original claim budget is preserved through these reads and both ledger/network queues. No IPC command or current voice-gate call supplies a claim, so the path remains inactive.

Successful ledger completion now transfers the withdrawal signal into StoredReply instead of cancelling it through normal Claim Drop. NativeEffects retains its exact planner signal roster until an atomic publish_planner handoff, checked under Runtime.local then the existing effects state mutex. An exact cancellation that wins that handoff suppresses the reply handle while preserving any committed history. Normal coordinator/caller drops disarm on success; dropped/unpublished replies withdraw their signal. The later normal-TTS owner must still revalidate output, actor and voice authority independently; publication is not audible output or a model readiness claim.

Every error after the first possible planner send owns one bounded correlated withdrawal, including registration-read or finalization/publication failures after a complete network response. The same retained coordinator then waits for pending-only retirement through the actual ledger owner. Core claim post-commit expiry/cancellation and worker claim-receipt delivery failure also retire their exact pending row; finish errors retire pending state without overwriting a committed reply. No lost handle is reconstructed, and cleanup failure reports unconfirmed pending-history reconciliation rather than claiming a successful suspension. No database operation, owner lookup, credential read, HTTP request, inference or output was invoked while checking source.


The subsequent normal-speech source handoff now returns PublishedReply rather than a raw StoredReply. Its withdrawal signal transfers atomically into the same effects owner's bounded published-source roster, retaining exact-source/actor/action cancellation until the next actual output owner consumes or drops it. This is an in-memory native ownership proof, not a deserializable history handle or synthesis activation.
