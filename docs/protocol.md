# Control protocol v2

The authenticated `POST /voice-analysis` boundary accepts the same bounded, explicitly correlated 1–10second16kHz PCM body as enrollment speaker analysis. It requires both operator-configured private `speaker-deployment.json` and `asr-deployment.json` sockets/revisions. One admitted request runs the two isolated lanes concurrently under independent worker request IDs; control-session mode/epoch invalidation cancels both. Both typed lane results are checked before returning same-session/epoch/utterance correlation and exact deployment revisions. This is nonstreaming transient analysis only. The current response explicitly abstains while calibrated owner, overlap and directed-intent evidence is unavailable; it creates no accepted turn, history, task or permission. Transcript and embedding are native-only transient data, never webview status or diagnostic content. The route is not a substitute for the required streaming pipeline, and unconditional abstention cannot satisfy positive owner acceptance.

Transport is authenticated TLS WebSocket; plaintext LAN action/media transport is forbidden. An authenticated connection must negotiate version, device/session identity and epochs before application messages. The contract library validates schema and freshness but does not authenticate a peer itself; callers must supply trusted session state from transport authentication. Authenticated control transport is implemented; action admission remains closed until owner setup and executor wiring.

Control v2 requires positive capture, playback and action epochs in every envelope and status response, including Hello. All three are monotonic within a session; missing fields, zero epochs and control v1 are rejected without fallback. The initial server session advertisement is v2. Pairing record/exchange schema v1, private audio JSON v1 and binary media framing v1 remain separately versioned. The older deployed `50dd7e2` v1 controller cannot connect to this companion; this source change is not deployed.

Capture-only mute/unmute advances capture epoch and leaves playback ownership unchanged. Deafen, pause, stop, lock and disconnect invalidate playback; output-device/profile replacement and explicit Settings setup cancellation also advance its native generation. Server output permission watches are bound to playback epoch and output modes, while capture/metadata-setup watches retain capture identity. Preview admission validates an explicit visible native Settings action separately from its ongoing output lease; microphone-only context changes must not terminate an already admitted preview.

Control JSON has a 65,536-byte limit. Unknown fields, message variants, versions and invalid UUID identities fail closed. Sequence numbers must strictly increase within the authenticated session. Device/session/epoch mismatches are stale. An action expires at `now >= expires_at_ms`; valid duration is at most 30 seconds. Persisted wall-clock expiration does not replace monotonic process deadlines.

Audio uses PCM signed 16-bit little-endian mono at 16 kHz, at most 320 samples per frame (20 ms), 64 queued frames, a 30-second transient-media TTL and 30-second maximum utterance. Image payloads are at most 4 MiB with one latest passive observation queued. Native capture/playback and authenticated audio transport implement their own stricter typed limits; image observation remains unimplemented. These limits do not establish live media qualification. Rejected frames are not persisted.

Tool requests bind UUID request/task/step/actor/target/grant IDs, device and session identities, sequence, capture/action epochs, expiration and optional exact approval. Actions have enumerated operation kinds; arbitrary shell/JavaScript/CDP commands are absent. Mutating action retry requires reconciliation. Unknown effect is a durable outcome, never success or permission to retry.

Capability manifests identify lane, driver, model/revision, deployment/locality, supported input formats, streaming/cancellation and actual health. Configured/downloading/responding is not ready. Readiness requires a successful actual capability probe for the same revision.

Trace records contain opaque correlation IDs, stage, host, deployment/config revisions, host-local monotonic queue/duration values, outcome and retry count. No content, credentials, transcripts, raw media or speaker vectors are valid trace fields. Cross-host wall clocks are never subtracted for latency. Missing observations remain unavailable.

## Pairing and control transport implementation

The companion now defaults to [LAN discovery and easy pairing](spark-discovery.md). This adds public UDP discovery on 9476 and a TLS `/pair-local` exchange during a one-device, five-minute setup window. A new installation opens that window by default; previously paired servers require explicit `serve --pairing`. `--manual-pairing` disables it. Selecting a discovered device uses trust on first use and pins the advertised certificate through normal TLS validation. The independent fingerprint/code workflow below remains the Advanced option. Discovery contains no credentials and does not grant owner, voice or action authority.

The server's opt-in `init <directory> <dns-name>` creates a private installation directory, a self-signed TLS certificate for the selected DNS name, and the authentication database. For Advanced pairing, `pair-code <directory>` writes a one-time random 256-bit pairing code to an owner-only local file, valid for five minutes and at most five incorrect attempts. Codes are read by the owner over the authenticated server administration channel; they are not advertised by a LAN endpoint. Advanced pairing requires independently checking the public certificate SHA-256 fingerprint. Neither pairing mode bypasses TLS verification.

`serve <directory>` binds TLS port 9474. `/pair` exchanges a valid one-time code for a fresh device UUID and bearer credential. The durable server database stores only the credential hash. `/control` requires that credential in the Authorization header before WebSocket upgrade, and a new server-selected session UUID on each connection. The first message must be Hello; its current local epochs become that connection's baseline. Later sequence/epoch checks apply. Local mode changes may only advance epochs, never reduce them. Action messages are rejected until owner enrollment and execution are implemented. Pairing alone never creates owner privileges or enables microphone capture.

Revocation is available through the authenticated local server CLI, takes effect on each control message, and closes idle sockets on the next bounded heartbeat interval. Socket frame/message caps are 65,536 bytes, handshake deadline ten seconds, and idle deadline thirty seconds. A new connection cannot resume or replay old queued actions. Authentication/pairing errors contain no supplied secret, and no request bodies enter logs.

Typed action arguments and action/accepted-intent revisions are immutable authorization inputs. Exact argument membership in a controller-derived accepted intent is required. An approval additionally binds the full typed payload and action revision; a changed prompt, amount, proposal digest, target or configuration cannot reuse it. Consequential operations reference an immutable owner-visible proposal plus revision and SHA-256 digest; an executor must resolve and verify that proposal before using it. The single native effect worker now consumes these primitives for explicit volume and executable-launch adapters. Native owner-selected setup and accepted-intent ingress remain incomplete; no public action authority is enabled.

VPN connection changes network state and requires exact local approval. Navigation arguments must be canonical HTTPS URLs without embedded credentials or whitespace/control characters. Read-page targets must be canonical HTTPS origins only. Cancel targets cannot be nil; Hello carries at most the seven known lanes without duplicates, including the initial handshake. Existing application databases with no version marker, multiple version rows, or unsupported versions are rejected before initialization/recovery writes.

The configured Spark endpoint may use an owner-selected DNS name or IP address on HTTPS port 9474; its verified certificate must include the same DNS/IP subject alternative name. There is no global DNS override or certificate bypass. The setup default reflects the currently discovered Spark address, but the saved endpoint is explicit and editable before pairing. A disconnect invalidates pending pair/load generations as well as active sockets, so a delayed result cannot reconnect silently.

## Durable execution ledger (schema 10)

Schema 10 adds bounded typed BrowserRead digest/count observations with no raw page text and rejects incompatible observation/finalization table/index/trigger layouts before advancing the version. Its dormant specialized finalization retains the full authorized request, requires resource settlement plus original current content authority, and checks policy and atomic/time bounds inside the final transaction. Actual native content remains borrowed by the live worker/checker; there is no transferable publication handle or activated read route. Schema 9 adds an immutable indexed browser-read retirement receipt table for exact duplicate-ack recovery. Current source validates its schema and bounded correlated metadata lookup, and atomically inserts a receipt/deletes its exact marker through a consumed borrowed live/recovery lease. Native ingress accepts only opaque actual-receive settlement proof; there is no reset command. Startup does not scan indefinite retirement history. Schema 8 adds a strictly validated singleton external browser-read ownership marker. Startup retains pending ownership as uncertain; any retained or malformed marker prevents new effect claims across the shared native owner. Generic finalization/reconciliation cannot clear it. The borrowed specialized core owner persists markers and distinguishes never-published cleanup from receipt-bearing possible-publication retirement. A separate one-entry completion mailbox reaches the same native worker for authenticated uncertain-row or duplicate-receipt recovery. Only validated receipt/readback permits an acknowledgement or reopening a previously blocked metadata snapshot. Active read publication and extension extraction remain unavailable. The specialized same-owner authorization and authenticated settlement path remain required before disclosure can be published. See [accepted browser reading](browser-reading.md).

`accept_intent` records the final controller-accepted actor, ordered exact payload list and explicit-submit scope. It is not exposed as a remotely supplied authority. `propose_action` stores immutable UUID revisions and the current head for each ordered step; changed arguments need a new accepted intent. `seal_task` requires the complete step count and freezes the plan before any claim. Grants are immutable scoped records; replacing scope means revoke plus new grant. Local approvals bind full arguments/revision and are revoked or consumed once.

`claim_action` checks durable scope, current grant/approval, expiry, active authenticated session, sealed uncancelled plan and prior-step success in a single transaction. It commits a unique dispatch and exact actor/device/session/epoch binding before an effect is sent. Duplicate claims cannot issue another permit. `finish_action` requires the same binding and a currently running step. Cancellation stops queued work and marks running dispatches for cancellation; a late verified success records the real effect without resurrecting the cancelled task. Crash recovery turns running steps/tasks into unknown effects and queued/waiting work into suspended state.

`reconcile_action` is reserved for authenticated local management with observed postcondition evidence; it resolves waiting/unknown outcomes without issuing an effect. Remaining work stays suspended and requires a new accepted task. No mutation can be blindly resumed by changing its state. The previous generic task-transition escape hatch is removed. These are durable core APIs; controller/owner-management wiring and live execution remain incomplete. No live database migration or effect workflow is claimed from static compilation.

Schema 4 adds insert-only native finalization outcomes bound to dispatch/target/action revision/actor/time in the original result transaction. Historical application success requires this exact original Success plus a fully validated matching Application (executable) or PackagedApplication observation. The latter preserves exact package registration identity and PID creation without claiming executable-file image verification. Task/step reconciliation cannot change that outcome or establish native-observed success. Existing schemas 1–3 upgrade transactionally without inventing finalization rows for legacy observations; unsupported schemas still reject before mutation.

Schema 5 adds private accepted-conversation history with exact device/session/utterance uniqueness and opaque native durable-turn handles. The original gate deadline survives consume, queue and transaction waits; the actual native effect worker owns acceptance, actor-filtered metadata recovery and exact-turn cancellation. Migration rejects an existing lookalike new table, and schema 5 validates its exact SQL, unique indexes and absence of attached triggers before mutation. Acceptance checks exact inserted fields before the final native authorization callback; recovery bounds the serialized body in bytes. Restart suspends unfinished conversation planning. These APIs remain dormant: the qualified runtime producer, concrete current-profile admission adapter, planner and task linkage are still unavailable. See [conversation admission](conversation-admission.md).

Schema 6 adds exact unique conversation-to-task linkage. A native-only deterministic resolver reads the accepted record, handles its retained assistant address and matches a whole open/launch learned-app command. It resolves the current actor-owned alias, checks an existing exact grant and atomically creates one sealed task/step/action with frozen alias/app/source revisions. No model payload or catalog label creates authority. Linked claim and final pre-effect revalidation compare the exact Action and original accepted actor/device/session/capture/action provenance. Existing non-linked native-management APIs retain their prior trusted-adapter contract; they do not constitute a voice acceptance path. Cancellation atomically updates the source and linked task, while the native owner signals only the exact active source lease before queue wait. Runtime qualification, concrete native current-context callbacks, grant-management and voice-to-producer wiring remain absent, so this source cannot issue live actions.

## Media packet and local speech adapter implementation

Binary `AVAU` packets carry protocol1, start/end flags, authenticated device/session/utterance UUIDs, capture epoch, contiguous media sequence, sample offset and a byte count followed by at most640bytes of16kHz mono signed16-bit PCM. The fixed header is82bytes. Session validation starts disabled, rejects gaps/stale identities, requires exact sample continuity and bounds utterance duration to30seconds of samples and host-monotonic reception time. It retains at most128 opaque utterance IDs for61seconds to reject reuse across pending30second inference results. Epoch invalidation must advance. Packet encode/decode does not authenticate or establish microphone authority. Client integration must reject already-old frames before the first send, impose send/idle deadlines, and invalidate on native queue gaps; native callback sequence cannot silently become a contiguous wire sequence after dropping frames.

The Linux controller `AudioClient` checks private same-UID Unix socket ownership/peer credentials, bounds request/response allocation and deadlines, admits one inference at a time, and supports explicit cancellation/epoch invalidation. Inference requires a configured lane and model revision; every result repeats that deployment identity and is decoded as exact ASR, speaker or TTS output before returning controller correlation (request, utterance, session, capture epoch). PCM uses strict base64 decoding, nonempty even byte counts and lane-specific sample/duration caps before consumption. The caller must also compare that correlation against the still-current accepted turn before publishing or acting. The generic constructor permits health/load inspection only. `avesra-server audio-health <private-socket>` is a content-free local operations command. These boundaries and measured native overlay events are implemented. Authenticated /voice-stream WSS forwarding and the native bounded producer exist in source; actual owner qualification, VAD/overlap/directness evidence and accepted-turn integration remain unavailable. Current source cannot enable normal voice readiness.


Schema 7 adds exact checked conversation-planner and immutable reply tables. One opaque accepted turn can produce one source-bound planner request; a fixed original 30-second monotonic admission survives queue, transport-view generation and reply persistence. The same actual native ledger worker claims/finalizes and observes exact-turn cancellation before durable cancellation is dequeued. Recovery exposes metadata only and suspends pending claims; it cannot recreate opaque request/reply handles. Answered history remains immutable, while an eventual playing answer needs its independent output lease cancellation. The paired model route and private reasoning adapter are source-integrated but unavailable without a qualified deployment; the normal TTS bridge is source-integrated while the qualified producer and live qualification remain incomplete. See [planner admission](planner-driver.md).


The planner-v1 /planner route accepts at most MAX_REQUEST_BYTES (32768) encoded bytes, covering the existing8192-byte decoded text and JSON escaping. A separate strict /planner/cancel carries only the exact original context and version. Both require the live paired session; authority uses the exact active actor-registration/action context, while cancellation uses the session's withdrawal-only digest. Retained replay bounds and unavailable qualification behavior are defined in [planner ingress](planner-ingress.md). No operation was invoked during source checks.


The native opaque-claim transport and same-worker finalization/publication are now source-integrated as described in [native planner ownership](native-planner.md). Pending-only retirement makes failed/unavailable requests suspended where cleanup commits, preserving all immutable answered/waiting_input replies. Successful native handoff preserves its signal, and exact cancellation remains effective until that handoff. There is still no qualified acceptance producer or configured qualified model, and no activated normal TTS producer. The native opaque PublishedReply consumer and `/normal-speech` bridge exist as described in [normal speech](normal-speech.md), with startup unavailable absent qualification.
