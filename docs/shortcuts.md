# Native global shortcuts

Microphone mute, deafen and show-overlay use one companion-owned Win32 message thread. RegisterHotKey with a null HWND posts to that owning thread; MOD_NOREPEAT prevents key-repeat toggles. Initial defaults are Ctrl+Shift+M, Ctrl+Shift+D and Ctrl+Shift+A. Registration results, including conflicts with other applications, are observed rather than inferred from saved preferences. These controls remain local while disconnected or minimized and never grant owner/voice readiness. Optional push-to-talk remains unavailable until its voice-cue and capture semantics are implemented and qualified.

Bindings are typed Ctrl/Alt/Shift plus an ASCII letter, digit or F1–F11. At least Ctrl or Alt is required; Windows-key and F12 reservations are excluded. Settings validate duplicates before persistence. Rebinding first registers the replacement under a fresh bounded ID, then unregisters the previous owned ID. Failed replacement leaves the old binding active where possible; unregister/rollback failure is explicitly unavailable. Numeric IDs are not reused during the worker lifetime, and queued WM_HOTKEY modifier/key fields must match the currently owned registration. Thread shutdown unregisters all owned IDs. No arbitrary key logging, input injection or arbitrary command dispatch exists.

The hotkey callback updates/publishes local safety state before enqueueing persistence. Overlay window operations happen outside Runtime.local. A native rebind result is persisted only after OS registration succeeds; failed persistence is reported separately from in-memory registration. The settings rows retain the approved card, description, keyboard chips, Change/record/Cancel states and inline conflict error from Settings.dc.html. Global registration is source-only during the gaming restriction; no shortcut registration, key press or app launch has been exercised.

The ownership and repeat rules follow Microsoft's [RegisterHotKey documentation](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-registerhotkey). Actual conflict, sleep/resume and desktop behavior remain unqualified.

The focused Settings editor owns a native ten-second recording token. Blur, close, lock, section disposal, Escape, Cancel or expiry ends recording; a stale completion cannot replace a newer token. The owner reports its existing registered chord to that editor instead of executing it. Other input uses layout-aware DOM `event.key`, never physical `event.code`; unsupported symbols, dead keys, AltGraph and Windows modifiers are rejected explicitly. Backspace removes a binding. Recording does not install a general keyboard hook.

Once a rebind enters the bounded native queue, its coordinator waits for the actual result even if posting the optional wake message fails. A 100 ms maximum message wait ensures accepted commands are drained; terminal registration failure publishes unavailable before replying. Generic settings saves reject changed shortcut fields so stale unrelated settings writes cannot overwrite an applied binding.

Reporting an owned chord does not consume the native recording token: explicit editor end or expiry releases it. The frontend subscribes before enabling Change and buffers a bounded early event until its exact native token returns. This prevents an event/IPC ordering race from leaving a recording editor whose next chord unexpectedly executes a control. Status reads carry a publication generation; a read started before a rebind cannot replace the later observed registration state.
