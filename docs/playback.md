# Native speech playback

## Explicit silent output recording

Native launch argument `--capture-output <absolute-new-WAV-path>` opts this process into diagnostic output recording before any stream can open. Invalid arguments or file creation fail launch. There is no WebView command or persisted setting. Every output callback in that process always submits silence, including after recording ends or fails. A diagnostic argument forwarded to an existing instance is refused without showing, focusing or modifying that instance; the unused recording stays armed/incomplete. A diagnostic instance also ignores second-instance activation requests. Normal launches into normal instances retain their existing behavior. Capture, source, Settings visibility, permission, device selection and readiness gates are unchanged; this option neither starts nor admits microphone capture or output.

Diagnostic mode suppresses the automatic startup greeting before preparation or synthesis so it cannot consume the recording. Explicit UI preview and every other permission/readiness gate remain unchanged. The first opened production output stream owns one recording. It starts at the first nonzero post-mix/post-device-format sample, includes subsequent callback silence, and retains the real device rate and stereo samples (replicated mono for other device layouts). It ends on stream disposal, recording failure, 120 seconds of samples or 120 seconds of elapsed recording time. An armed stream with no signal expires after 120 seconds. Later streams stay silent and cannot restart recording. Launch a separate diagnostic process for another recording. The existing PlaybackReference path alone is insufficient because it omits idle callback silence and does not suppress hardware output.

Only preallocated bounded buffers and nonblocking bounded communication run in the callback. A native writer owns WAV and sidecar files; queue exhaustion terminates recording without resuming sound. Files use create-new semantics. The sidecar identifies diagnostic postmix-before-silencing provenance, hardware_silent, launch UTC/process-monotonic origin, first sample UTC and monotonic offset, endpoint rate/channel count, stereo WAV frame count, duration and terminal reason. An armed/incomplete sidecar is never completion evidence. WAV is IEEE float32 stereo. UTC is expressed as Unix epoch nanoseconds in decimal strings. This instrumentation does not prove audible delivery, microphone input, speaker identity, qualification or accepted-task completion. Existing preview telemetry in this mode observes the diagnostic mix before hardware silencing; screenshots must be labeled accordingly.

Entry points: native main argument parsing (covered before runtime setup); all CPAL output sample-format callbacks (covered after the real mixer); PlaybackReference/preview/normal speech (authority unchanged, diagnostic provenance above); microphone capture and IPC filesystem access (unaffected, no new entry point). Static build/review and root-owned explicit real media observations apply under the owner's no-automated-tests instruction.

## Voice atmosphere output contract (Plan 002)

Digital (default selected preset) and Human are local sound settings, independent of the selected generated voice. The master starts disabled for existing and new settings. Digital supplies bass emphasis, an optional parallel pitch double, spacious reverb and repeating stereo echoes over the Galaxy recording; Human starts with transparent processing and background disabled. The owner's latest Digital defaults are Compression 40, Background 85, Bass 100, displayed Reverb 50 (stored amount 100), Harmonizer 75 at half a semitone lower, Presence 85 and Echo 10, with +105/+65 ms left/right echo spacing. Both effect/background layers are enabled within Digital and Galaxy ambience is selected. Each preset retains independent amounts. Native revisioned partial controls update these settings and master volume without restarting a sentence or changing capture, action or playback authority. Whole-settings writes cannot overwrite a newer sound revision. Runtime bypass applies before persistence and remains effective on a failed save.

Both generated-reference preview and accepted speech deliver clean PCM into one native mixer. Master speech volume is applied there exactly once, including to atmosphere. Off ramps to dry over at most 30 ms without restarting speech; deafen, pause, stop, lock, disconnect and gate withdrawal silence everything immediately. DSP and loops start only with submitted speech, never while waiting for TTS. Native stereo output keeps speech centered with stereo atmosphere; non-stereo layouts use explicitly reported replicated mono. Callbacks use prepared DSP/buffers and bounded nonblocking communication, never model/file/network work or allocation.

The atmospheric background uses the owner's supplied 20-second Galaxy recording, bundled as lossless stereo PCM. Preparation resamples it to the selected output rate and overlaps the last second into the first, retaining a 19-second loop. Preparation occurs before playback callbacks; failures prevent output admission instead of substituting an unrelated sound. Playback enters two seconds into the prepared loop so short replies have an audible bed immediately. Voice effects process only speech; the recording has its own background gain and ducking. The source stays bundled with the app and does not depend on the Downloads folder after import.

Live tuning retains a full centered voice under an optional pitch-shifted copy with adjustable depth (default half a semitone lower), with independent Voice presence, Reverb and Echo amounts. Harmonizer replaces the rejected synth vocoder; it reuses the actual speech waveform, preserving its inflection. Two crossfaded delay heads per channel produce the shifted return, with offset phases for mild stereo width and prepared high/low-pass filters. A fixed 70 ms buffer is allocated before output callbacks; no inference is needed. The clear voice is never reduced as the double increases; its filtered parallel return is mixed at up to 120% gain and does not feed the reverb/echo inputs. The existing internal `texture` amount now controls Harmonizer; zero remains fully off, so zero still preserves the dry-voice comparison. All amounts remain 0–100; missing presence/echo fields in saved presets migrate to 50/35. Human does not apply these Digital-specific amounts. Sliders coalesce pending edits by preset and field while dragging, with at most one slider write in flight; the master bypass remains immediate. Galaxy gain has enough range for an audible bed without increasing master volume. Explicit Repeat preview replays the same saved reference after each completed preview and a short gap, without regeneration. Stop repeating finishes the current preview, and leaving the panel, disconnecting, pausing, deafening or hiding the window prevents further repeats. Each repeat retains normal native preview admission and deadlines.

Final source submission, final mixed-tail submission and estimated device drain are distinct observations. Each admitted utterance starts with 120 ms of local lead-in before consuming voice samples, allowing the endpoint and ambience to settle without fading away initial consonants. All source samples are preserved. Existing source totals/acknowledgements remain unchanged; the local lease remains owned until the mix drains. After the last source sample, effects/background retain up to 200 ms at level, then smoothly fade over up to 1600 ms (1800 ms total). This tail is shortened or omitted to fit the admitted deadline and device drain budget. Preview local packet lifetime reserves four seconds after source duration, capped at the existing 32-second packet maximum; public transport, source acknowledgements and remote authority lifetimes remain unchanged. Local drain wait is bounded to 3100 ms. Submitted references include actual post-format channel samples during lead-in, speech and tail. Display energy is observation only, and lead-in/tail cannot assert speaking or echo readiness. Later text below describes the original source-only renderer where superseded by this section.

Left/right echo spacing controls each add 0–400 ms per repeat to the existing 120/180 ms stereo spacing; zero retains the current tune. Three attenuating taps use those intervals, so the longest possible repeat is 1740 ms. Missing timing values migrate to zero and Human defaults to zero; the latest owner-approved Digital defaults use +105 ms left and +65 ms right. Values are saved per preset, and do not delay the dry voice or background. A separate atomic mailbox publishes the timing pair and Harmonizer depth; ordinary gain/bypass preferences retain their existing atomic mailbox. Both are smoothed on the audio thread, and a preset change can cross one callback control-refresh boundary between timing and gain updates. Neither mailbox grants playback authority. Echo buffers allocate a fixed two seconds before callbacks; no feedback can extend the bounded tail.

Reverb displays 0–100% with twice the old wet-return range: the UI divides the native 0–200 amount by two. The old 80% tune therefore displays 40%, with identical sound; the latest approved default is displayed 50% (stored 100). The dry voice and finite tail bounds are unchanged. Native validation and the atomic gain mailbox retain the full integer reverb range.

Harmonizer pitch is independent of its amount: one octave below to one octave above, in half-semitone steps, with an owner-approved default of 0.5 semitones lower. Zero is an unshifted parallel copy, while Harmonizer amount zero disables the return. Saved presets missing depth migrate to 0.5 semitones; the selected voice and all existing amounts are preserved. Native settings retain the `harmonizer_depth` field as signed -24..24 downward half-semitones (negative values shift upward), preserving earlier saved positive depths. The UI displays musical pitch -12..+12 semitones, reversing that storage sign. The timing mailbox also publishes depth, and the audio thread smoothly changes its pitch ratio without allocating or restarting speech. The shared mixer applies it to both preview and reply; Human ignores the Digital-only return.

Verification follows the owner's existing no-tests override: static/build checks and direct source review. Live audio quality, CPU/latency, stereo, interruption and loop-seam listening remain separately unqualified until measured.

Capture and playback use separate typed frames. Capture is always 16 kHz mono for the configured ASR/speaker contract. Speech output accepts only explicitly negotiated 16 or 24 kHz mono PCM; the Qwen lane currently returns 24 kHz. The output rate is never inferred from a byte count or silently treated as the capture rate. Ingress binds the authenticated session before constructing frames carrying independent playback epoch, utterance identity, contiguous sequence, exact valid sample count and final-frame status. Maximum frame duration is 20 ms; a short frame is valid only at the end of an utterance.

The native media worker owns one output device and bounded queues. Conversion uses preallocated band-limited filtering at the device's advertised rate, prepared off the callback. A device/configuration/epoch change disposes queued PCM, converter history and partial output. A final frame explicitly flushes a bounded filter tail; a missing frame or underrun after playback starts invalidates that utterance instead of joining speech across an unexplained gap. Before start, a small bounded prebuffer may wait only within the utterance's monotonic budget. All output paths recheck local deafen/pause/lock/disconnect gates within callbacks, emitting silence immediately when invalidated.

References describe the samples actually submitted to the output device, their typed sample rate, utterance/epoch and CPAL playback clock. They are transient inputs to echo handling, not identity evidence, microphone recordings or retained speech history. Reference overflow, unsupported rate conversion, missing clock correlation or discontinuity withdraws echo readiness. Timestamp availability alone does not prove echo cancellation. Assistant output and desktop audio must never be promoted to an owner command merely because a speaker embedding resembles the owner.

Playback interruption closes the local output gate before requesting upstream cancellation. Late chunks for the old utterance or epoch are discarded. The overlay's speech renderer consumes measured submitted output, and disappears on gate closure or stale signal. Acknowledging a network audio chunk is distinct from observing that device playback began.

The native renderer retains at most64 admitted utterance UUID tombstones in fixed storage for33seconds, longer than any packet's32second lifetime. Completion and filter reset do not remove these entries. Reused identities and exhausted admission capacity fail closed; there is no callback allocation or unbounded history. Future network ingress must independently bind the authenticated control session before creating native frames.

Current implementation boundary: native playback has separate typed 16/24 kHz frames with utterance/epoch/deadline/sequence/final-sample validation. Qwen's 24 kHz path is the default output configuration. It prefers a matching backend-advertised rate, otherwise uses the advertised default output rate with preallocated Rubato sinc conversion (8–192 kHz). Both paths prebuffer two frames or a complete short utterance, with a 250 ms waiting limit, and require one unchanged deadline across the utterance. Conversion trims startup delay, explicitly feeds bounded zeros after the final source sample, emits exactly `ceil(input_samples * output_rate / input_rate)` samples, and resets history before reuse. Reference frames carry actual post-format-conversion device-rate samples and the corresponding hardware playback clock. A rate mismatch, malformed frame, expired deadline, mid-utterance underrun, sequence gap or reference overflow closes that device attempt.

The converter uses [Rubato's preallocated processing API](https://docs.rs/rubato/0.16.2/rubato/trait.Resampler.html); allocation-producing partial-buffer helpers are not used in callbacks. Filter construction and buffers are allocated before stream creation. Filtering still consumes callback CPU, which remains unmeasured and may require relocation to a bounded worker during final latency qualification. Accepted synthesis ingress and native session binding are source-integrated in normal-speech.md; the qualified producer and echo processing remain pending. Submitted-reference speaking events follow [playback telemetry](playback-telemetry.md). No playback device has been opened during the gaming restriction. No latency, interruption or echo-quality claim follows from static compilation.

## Independent output ownership

Native playback configuration, queued frames and device attempts use `LocalState.playback_epoch`, independently of capture epochs. Mic mute/unmute neither reopen the output device nor clear its queue. Output generation changes synchronously close old attempt permission and clear queued output before worker/OS completion; deafen, pause, stop, lock, disconnect, output-device/profile changes invalidate it. Explicit setup close/cancel invalidates only a Settings preview lease; it preserves an accepted reply lease. A capture-only device change does not relabel old playback frames. Audio-device failure withdraws unqualified voice readiness and closes both lanes, bound to the failed lane's own generation so a late callback cannot invalidate its replacement. This is source ownership enforcement, not playback qualification; explicit native setup-preview integration is described below.

Explicit preview uses a separate70second native output-only lease and waits for the exact preview UUID/epoch/device-ready publication before accepting frames. A maximum30second asset gets a fixed duration+2second playout deadline (at most32seconds), and callback tombstones now retain UUIDs33seconds. The last20ms frame is held until the transport End validates exact totals. Preview applies the native0 to100percent assistant gain before enqueue; submitted references contain the actual post-gain device samples, not endpoint/system-volume mutations. A final reference marks submission only. The device remains open through CPAL's bounded callback/playback-time estimate plus50ms; missing or greater-than1second estimates use a conservative bounded1second fallback plus50ms. This draining estimate is unqualified and does not prove audible delivery. Deafen/stop/pause/lock/disconnect cancel immediately, including during drain.


Accepted replies now use the same typed renderer through a distinct native output purpose, with exact PublishedReply cancellation and caller withdrawal in the callback gate. Current microphone changes do not withdraw accepted action/output authority. Both preview and accepted output retain shared admission until the actual media worker acknowledges a withdrawn configuration after native stream construction/destruction. No async deadline frees a still-owned native job. See [normal speech ownership](normal-speech.md) for controller reservation, strict early-audio framing, current unavailable qualification and submission-only completion.
