# Native speech playback

Capture and playback use separate typed frames. Capture is always 16 kHz mono for the configured ASR/speaker contract. Speech output accepts only explicitly negotiated 16 or 24 kHz mono PCM; the Qwen lane currently returns 24 kHz. The output rate is never inferred from a byte count or silently treated as the capture rate. Frames carry session/capture epoch, utterance identity, contiguous sequence, exact valid sample count and final-frame status. Maximum frame duration is 20 ms; a short frame is valid only at the end of an utterance.

The native media worker owns one output device and bounded queues. Conversion uses preallocated band-limited filtering at the device's advertised rate, prepared off the callback. A device/configuration/epoch change disposes queued PCM, converter history and partial output. A final frame explicitly flushes a bounded filter tail; a missing frame or underrun after playback starts invalidates that utterance instead of joining speech across an unexplained gap. Before start, a small bounded prebuffer may wait only within the utterance's monotonic budget. All output paths recheck local deafen/pause/lock/disconnect gates within callbacks, emitting silence immediately when invalidated.

References describe the samples actually submitted to the output device, their typed sample rate, utterance/epoch and CPAL playback clock. They are transient inputs to echo handling, not identity evidence, microphone recordings or retained speech history. Reference overflow, unsupported rate conversion, missing clock correlation or discontinuity withdraws echo readiness. Timestamp availability alone does not prove echo cancellation. Assistant output and desktop audio must never be promoted to an owner command merely because a speaker embedding resembles the owner.

Playback interruption closes the local output gate before requesting upstream cancellation. Late chunks for the old utterance or epoch are discarded. The overlay's speech renderer consumes measured submitted output, and disappears on gate closure or stale signal. Acknowledging a network audio chunk is distinct from observing that device playback began.

The native renderer retains at most64 admitted utterance UUID tombstones in fixed storage for31seconds, longer than any packet's30second lifetime. Completion and filter reset do not remove these entries. Reused identities and exhausted admission capacity fail closed; there is no callback allocation or unbounded history. Future network ingress must independently bind the authenticated control session before creating native frames.

Current implementation boundary: native playback has separate typed 16/24 kHz frames with utterance/epoch/deadline/sequence/final-sample validation. Qwen's 24 kHz path is the default output configuration. It prefers a matching backend-advertised rate, otherwise uses the advertised default output rate with preallocated Rubato sinc conversion (8–192 kHz). Both paths prebuffer two frames or a complete short utterance, with a 250 ms waiting limit, and require one unchanged deadline across the utterance. Conversion trims startup delay, explicitly feeds bounded zeros after the final source sample, emits exactly `ceil(input_samples * output_rate / input_rate)` samples, and resets history before reuse. Reference frames carry actual post-format-conversion device-rate samples and the corresponding hardware playback clock. A rate mismatch, malformed frame, expired deadline, mid-utterance underrun, sequence gap or reference overflow closes that device attempt.

The converter uses [Rubato's preallocated processing API](https://docs.rs/rubato/0.16.2/rubato/trait.Resampler.html); allocation-producing partial-buffer helpers are not used in callbacks. Filter construction and buffers are allocated before stream creation. Filtering still consumes callback CPU, which remains unmeasured and may require relocation to a bounded worker during final latency qualification. The actual synthesis ingress, session binding, speaking events and echo processing remain pending. No playback device has been opened during the gaming restriction. No latency, interruption or echo-quality claim follows from static compilation.

## Independent output ownership

Native playback configuration, queued frames and device attempts use `LocalState.playback_epoch`, independently of capture epochs. Mic mute/unmute neither reopen the output device nor clear its queue. Output generation changes synchronously close old attempt permission and clear queued output before worker/OS completion; deafen, pause, stop, lock, disconnect, output-device/profile changes and explicit setup close/cancel invalidate it. A capture-only device change does not relabel old playback frames. Audio-device failure withdraws unqualified voice readiness and closes both lanes, bound to the failed lane's own generation so a late callback cannot invalidate its replacement. This is source ownership enforcement, not playback qualification or a setup-preview implementation.
